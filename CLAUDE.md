# QR-меню и заказ в зале — SaaS для ресторанов Кыргызстана

## Что строим
Гость сканирует QR на столе, открывает меню в браузере (без приложения), сам делает заказ,
вызывает официанта и просит счёт. Заказ сразу уходит на экран кухни и официанту.
Ресторан платит платформе ежемесячную подписку. Комиссию с заказов не берём.

**Онлайн-оплаты гостями НЕТ.** Платформа не принимает и не проводит деньги гостей:
гость платит официанту наличными или картой, официант отмечает «счёт закрыт».
Онлайн-оплата (ELQR) появится позже, когда будет ИП/ТОО — не закладывать её в MVP.

Полное ТЗ: https://claude.ai/artifact/GXQw8JmGzG4rnRWRiWkJ3K
Макеты экранов: https://claude.ai/artifact/HLAXMH1MUM3prxDejYreab

## Роли
- Гость — без регистрации, ссылка из QR содержит ресторан и стол
- Официант — телефон, PWA
- Кухня/бар — планшет, PWA, тёмная тема
- Администратор ресторана — панель (компьютер/телефон)
- Супер-админ платформы — управление ресторанами и подписками

## MVP (делать только это)
1. Меню гостя: категории, блюда (фото, описание, цена в сомах, вес), модификаторы, комментарий,
   метки «хит/острое/халяль/нет в наличии», языки RU / KY / EN
2. Подсказки «к этому берут» в карточке блюда и корзине (связки задаёт ресторан)
3. Корзина → заказ; ресторан выбирает: сразу на кухню или сначала подтверждение официантом
4. Статус заказа у гостя в реальном времени; дозаказ в тот же счёт стола
5. Кнопки «позвать официанта» и «принести счёт» (выбор: наличные / карта)
6. Лента официанта: вызовы, заказы на подтверждение, «готово — забрать», закрытие счёта
7. Экран кухни (KDS): колонки Новые / Готовятся / Готово, таймер, цеха кухня/бар
8. Панель ресторана: редактор меню, стоп-лист, столы + печать QR (PDF), сотрудники и роли,
   настройки (часы, % обслуживания, логотип, акцентный цвет), выручка/заказы/средний чек/топ блюд
9. Умный отзыв после закрытия счёта: 4–5★ → ссылка на 2GIS ресторана, 1–3★ → только владельцу
10. Telegram-бот владельцу: вечерний отчёт + алерты (заказ ждёт дольше нормы, плохой отзыв, стоп-лист)
11. Супер-админка: рестораны, статус подписки (ставится вручную), блокировка в режим «только меню»

Не в MVP: онлайн-оплата, доставка, бонусы, банкеты, автоперевод меню, интеграции с кассами (iiko, Poster).

## Стек
- TypeScript везде, монорепозиторий (pnpm workspaces)
- `apps/web` — Next.js (App Router), PWA: гость, официант, кухня, панель — разные маршруты
- `apps/api` — NestJS, REST + WebSocket (Socket.IO) для realtime
- PostgreSQL + Prisma; Redis — pub/sub и очереди (BullMQ)
- Фото — S3-совместимое хранилище, сжатие в WebP
- Docker Compose для локального запуска
- Тесты: Vitest (unit), Playwright (основной путь гостя)

## Модель данных (основные сущности)
Restaurant (tenant), Venue, Staff (role: waiter | kitchen | manager), Table (signed QR token),
Category, Dish, ModifierGroup, Modifier, Upsell, TableBill (open/closed), Order, OrderItem,
WaiterCall, Review, Plan, Subscription.
Каждый запрос фильтруется по restaurantId — данные ресторанов строго изолированы.

## Правила
- Деньги храним в тыйынах (целые числа), валюта KGS, показываем «1 250 сом»
- Часовой пояс Asia/Bishkek
- Все тексты интерфейса через i18n (ru, ky, en); кыргызские строки длиннее — вёрстка должна это выдерживать
- Mobile-first: меню гостя открывается за ≤2 c на среднем Android по 3G/4G
- Кнопки ≥ 44 px, контраст текста ≥ 4.5:1
- QR-ссылка стола подписана; лимит заказов с одного устройства
- Вход персонала: телефон + PIN (SMS — позже)
- Не добавлять функции вне списка MVP без запроса
